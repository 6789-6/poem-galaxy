# 诗云「黑金宇宙歌剧」改版设计

## 1. 目标

将现有 `poem-galaxy` 收敛为一个华丽、震撼、可持续维护的三维诗歌视觉作品。新版以「黑金宇宙歌剧」为唯一视觉方向，以桌面端电影级效果为主，同时保留移动端的完整功能和自适应性能降级。

项目继续使用 React、TypeScript、Vite、Three.js、React Three Fiber 与 GitHub Pages。线上地址保持为 `https://6789-6.github.io/poem-galaxy/`，部署仍由 `main` 分支触发现有 GitHub Actions 工作流。

## 2. 已确认决策

- 产品定位：视觉作品展示优先，但不牺牲现有探索能力。
- 视觉方向：C「黑金宇宙歌剧」。核心元素为极深黑背景、熔金高光、紫色能量、巨大吸积盘、电影化标题和克制的 HUD。
- 功能范围：保留搜索、朝代筛选、诗人星域、诗作阅读、关系网络、巡游模式、键盘返回和界面隐藏。
- 内容规模：接入更大的公开古典诗词数据集，采用构建期标准化和运行时按需加载，不追求全量语料。
- 设备策略：桌面端完整电影级效果；移动端自动降低粒子、DPR 和后期效果，但功能保持完整。
- 架构方案：重构为单一生产入口和一套电影级宇宙引擎；不继续叠加现有多代入口与样式。
- 部署方式：保留现有 Vite `/poem-galaxy/` 基础路径与 GitHub Pages Actions 发布方式。

## 3. 当前问题与改造边界

仓库当前同时保留多套 App、场景、入口和 CSS 皮肤。生产入口由 `index.html` 指向 `src/globe-entry.tsx`，但 `src/main.tsx`、`src/App.tsx` 以及多套 Globe、Video 和 Research 组件仍然存在。重复实现使功能、视觉和数据修改容易落到非生产路径，也增加包体、维护和回归风险。

本次改造只处理诗云站点本身：

- 将生产入口统一为 `src/main.tsx` 和 `PoemGalaxyApp`。
- 在功能对齐测试通过后删除不再被使用的旧入口、旧场景和重复样式。
- 保留可验证的诗人、诗作与关系数据。关系记录必须包含类型和来源说明；没有来源的现有生成关系在转换时删除，不生成虚假的人物关系。
- 不引入后端服务、用户系统、登录、评论、收藏同步或运行时 GitHub API。
- 不把完整上游诗词仓库或未经筛选的数百兆语料直接放入首包。

## 4. 视觉与体验设计

### 4.1 总览状态

页面为全屏三维舞台。一个倾斜的巨大诗歌吸积盘占据主要视野，核心使用熔金白光，外圈使用深紫与少量红橙能量。背景保持极深黑，避免普通蓝紫渐变 SaaS 观感。

默认 HUD 只显示：

- 左上角「诗云」与简短英文副标题；
- 左侧六个朝代入口；
- 右上角真实诗人、诗作数量与当前质量档位；
- 底部居中的全局搜索；
- 右下角简短操作提示。

页面空闲时 HUD 逐步淡出，星体仍保持低速运动。按 `H` 可主动隐藏或显示界面。

### 4.2 开场演出

首次进入执行 3—4 秒的镜头演出：镜头从远处穿过低密度星尘，吸积盘从黑暗中显现，随后标题和 HUD 分层出现。

- 开场可跳过，不阻塞搜索和键盘操作。
- 同一会话只完整播放一次。
- `prefers-reduced-motion: reduce` 下直接进入稳定总览。
- 移动端使用更短、更低成本的 1 秒淡入，不执行穿越镜头。

### 4.3 聚焦状态

点击诗人或搜索命中后，镜头飞入对应主星。右侧只在选中内容后出现上下文面板：

- 诗人状态显示生卒、朝代、简介、主题、代表作和可验证关系；
- 诗作状态显示题名、作者、体裁、全文、主题和返回路径；
- 关系状态将相邻诗人和关系航线置于视觉中心；
- 巡游状态依次访问精选诗人和名篇，并允许随时退出。

信息面板使用暗色半透明材质、熔金标题与紫色层级线，不用大面积玻璃卡片覆盖星体。

### 4.4 移动端

移动端保留三维星体和全部功能，但界面改为底部 Sheet：

- 朝代、搜索、模式切换使用底部控制区；
- 诗人和诗作内容在可滚动 Sheet 中呈现；
- 关系网络减少同时显示的节点和航线；
- 禁用景深，降低 Bloom、粒子数和 DPR；
- 触控目标不小于 44 CSS 像素，并支持安全区内边距。

## 5. 应用架构

### 5.1 单一生产入口

`index.html` 只加载 `src/main.tsx`。`main.tsx` 只负责挂载 `PoemGalaxyApp`，不包含业务状态或场景逻辑。

建议目录边界：

```text
src/
  app/PoemGalaxyApp.tsx
  state/galaxy-reducer.ts
  scene/CosmicOperaScene.tsx
  scene/layers/AccretionDisk.tsx
  scene/layers/DynastyBands.tsx
  scene/layers/PoetStars.tsx
  scene/layers/PoemDust.tsx
  scene/layers/RelationArcs.tsx
  scene/CameraDirector.tsx
  scene/ScenePostProcessing.tsx
  ui/CinematicIntro.tsx
  ui/DynastyNavigator.tsx
  ui/GlobalSearch.tsx
  ui/FocusPanel.tsx
  ui/ModeDock.tsx
  ui/MobileSheet.tsx
  data/client.ts
  data/schema.ts
  workers/search.worker.ts
```

### 5.2 状态模型

页面使用一个 reducer 管理以下稳定状态：

- `overview`
- `poet`
- `poem`
- `network`
- `tour`

选择事件统一为 `SELECT_POET`、`SELECT_POEM`、`SET_DYNASTY_FILTER`、`ENTER_NETWORK`、`START_TOUR`、`BACK` 和 `RESET`。搜索、点击三维节点、点击列表和巡游模式都通过同一事件接口改变状态。

场景层只接收结构化状态与回调，不直接操作搜索框或 DOM 面板；界面层不直接修改 Three.js 对象。`CameraDirector` 根据状态计算镜头目标，保证鼠标、搜索和关系模式不会各自维护一套相机逻辑。

### 5.3 组件责任

- `CosmicOperaScene`：组合场景层，不持有内容搜索逻辑。
- `AccretionDisk`：负责黑金吸积盘和核心光场。
- `DynastyBands`：负责朝代空间分布和筛选透明度。
- `PoetStars`：负责诗人主星、命中检测和标签。
- `PoemDust`：负责大规模诗作粒子，不渲染文本面板。
- `RelationArcs`：只渲染真实关系数据。
- `CameraDirector`：负责总览、飞入、返回和巡游镜头。
- `ScenePostProcessing`：按质量档位启用 Bloom、色调映射和可选景深。
- `GlobalSearch`：发送 Worker 查询并展示结果，不直接移动镜头。
- `FocusPanel`：根据 reducer 状态展示诗人、诗作或关系内容。
- `MobileSheet`：复用相同内容模型，不维护第二套业务状态。

## 6. 数据设计

### 6.1 来源与版权

新增古典诗词来自 MIT 授权的 `chinese-poetry/chinese-poetry` 数据库，导入基线固定为提交 `b8594f81a89752241442f2ce267d6f66f96704ee`。站点仓库保留来源、提交号、MIT License 与转换说明。

数据范围限于公共领域古典作品。近现代诗只保留作者、题名和主题索引，不加入未经明确授权的全文。

### 6.2 规模与筛选

标准化语料必须满足：

- 至少 15,000 首有效古典作品；
- 至少 1,000 位有作品关联的作者；
- 覆盖诗经、楚辞、汉魏六朝、唐、宋、元明清；
- 保留当前精选诗人与名篇；
- 总量上限为 20,000 首，避免滑向全量语料方案。

筛选过程确定且可复现：先保留当前精选记录，再按朝代配额、作者代表性和稳定哈希顺序补足。转换脚本拒绝空标题、空作者、空正文、重复作品和无法映射的朝代。

### 6.3 产物

构建期数据脚本生成：

- `manifest.json`：版本、来源提交、真实数量、分片清单与校验值；
- `featured.json`：首屏精选作者、名篇和带来源说明的关系；
- `authors.json`：作者元数据与作品分片映射；
- `search-index.json`：作者、题名、名句和主题的紧凑索引；
- `poems/<dynasty>-<n>.json`：每片最多 500 首作品；
- `THIRD_PARTY_NOTICES.md`：上游来源与 MIT License。

所有运行时 URL 通过 `import.meta.env.BASE_URL` 生成，确保 GitHub Pages 子路径可用。UI 统计只读取 `manifest.json`，不得硬编码夸大数字。

关系记录统一为 `fromId`、`toId`、`type`、`sourceLabel` 和可选 `sourceUrl`。转换测试拒绝没有 `sourceLabel` 的关系；界面只在详情中展示简短来源，不把推测或空间距离伪装成历史关系。

### 6.4 运行时数据流

1. 首屏只加载应用代码、`manifest.json` 和 `featured.json`。
2. 首次搜索时启动 `search.worker.ts` 并加载紧凑索引。
3. 进入朝代、诗人或诗作时加载对应分片。
4. 已加载分片保存在内存 Map 中并依赖浏览器 HTTP 缓存，不增加首版 IndexedDB 复杂度。
5. Worker 只返回 ID 与排名；主线程通过数据客户端解析内容并更新 reducer。

## 7. 性能与自适应质量

### 7.1 质量档位

- `cinematic`：面向桌面独立显卡或高性能集显，完整粒子、Bloom、色调映射和受控景深。
- `balanced`：减少粒子和后期采样，保留黑金吸积盘与关系航线。
- `performance`：面向移动端、低核心设备和减少动态偏好，关闭景深、降低 DPR、粒子和持续动画。

初始档位根据视口、设备像素比、硬件并发数、减少动态偏好与一次短帧率采样决定。运行中若连续低于目标帧率，最多自动下降一个档位；不自动升档，避免视觉反复抖动。

### 7.2 预算

- 首次加载的压缩 JavaScript 不超过 700 KiB；
- 首屏精选数据压缩后不超过 250 KiB；
- 首屏不加载全量搜索索引或朝代分片；
- 1440p `cinematic` 目标稳定 50 FPS 以上；
- 移动端 `performance` 目标稳定 30 FPS 以上；
- 页面隐藏时暂停帧循环中的非必要更新；
- Postprocessing 和巡游逻辑允许动态导入。

## 8. 失败与降级

- 数据分片失败：保留精选内容，面板显示可重试状态，不清空当前选择。
- 搜索索引失败：允许对已加载精选内容执行轻量搜索，并提示搜索范围受限。
- Worker 不可用：在主线程对紧凑索引分批搜索，每批主动让出事件循环。
- WebGL 创建失败：进入 DOM/CSS 静态星图模式，不创建第二套业务状态，继续复用相同 reducer、朝代导航、搜索和诗人/诗作面板。
- WebGL 上下文丢失：先暂停 UI 状态变化并尝试恢复；恢复失败后进入静态模式。
- 字体或装饰资源失败：使用本地字体栈，不影响正文和操作。
- 空搜索结果：显示明确的空状态和可尝试的作者、题名与意象示例。

## 9. 可访问性

- Canvas 之外保留语义化的可操作导航和内容镜像；功能不依赖鼠标悬停。
- 所有按钮、搜索结果和 Sheet 支持键盘焦点与可见焦点环。
- `Escape` 按 `poem → poet → overview` 层级返回；`H` 只控制装饰 HUD，不隐藏当前焦点内容。
- 动态加载和模式切换通过 `aria-live` 提供简短状态，不朗读持续帧动画。
- 颜色不是朝代和选择状态的唯一表达；同时使用标签、位置和选中标记。
- 移动端触控目标不小于 44 CSS 像素。

## 10. 测试设计

### 10.1 自动测试

- 数据转换：许可证元数据、来源提交、去重、朝代映射、数量边界与分片校验。
- Reducer：总览、诗人、诗作、关系、巡游、返回与重置路径。
- 搜索 Worker：作者、题名、名句、主题、空结果和失败回退。
- 组件：键盘搜索、朝代切换、面板返回、移动 Sheet 和减少动态模式。
- 场景合同：质量档位、图层启停、关系数据真实性和相机目标。
- 构建合同：所有数据 URL 使用 Pages 基础路径，产物不含绝对本地路径。

### 10.2 浏览器验收

桌面使用 1440 × 1000，移动端使用 390 × 844，并覆盖：

- 开场可跳过且不阻塞操作；
- 总览、搜索、朝代、诗人、诗作、关系和巡游完整可用；
- 移动 Sheet 无内容截断或横向溢出；
- 减少动态模式不执行持续镜头与高成本后期；
- WebGL 失败和分片失败的可用降级；
- 控制台无未处理错误和无障碍严重问题；
- 实测帧率、首包与数据请求满足预算。

## 11. GitHub Pages 发布

开发在 `aho/poem-galaxy-cosmic-opera` 分支完成。实现和验证通过后合并到 `main`，继续使用 `.github/workflows/deploy.yml`：

1. Checkout；
2. Node 20；
3. 安装锁定依赖；
4. 运行测试、类型检查和生产构建；
5. 上传 `dist/` Pages artifact；
6. 使用 `actions/deploy-pages` 发布。

发布后必须等待 Actions 成功，并验证：

- `https://6789-6.github.io/poem-galaxy/` 返回 200；
- HTML、JS、CSS、manifest、featured、search index 和至少一个朝代分片均可加载；
- 线上桌面与移动端主要状态可操作；
- 控制台无未处理错误；
- 仓库 Pages Source 仍为 GitHub Actions。

## 12. 验收标准

- 第一眼符合「黑金宇宙歌剧」的华丽、震撼目标，而不是普通青紫玻璃控制台。
- 只有一个生产入口和一套生产场景、状态与样式系统。
- 搜索、朝代、诗人、诗作、关系、巡游和界面隐藏全部可用。
- 古典诗词语料达到 15,000—20,000 首和至少 1,000 位作者，来源与许可证清晰。
- 页面统计来自真实数据清单。
- 桌面完整效果、移动完整功能和自动质量降级均通过验收。
- 自动测试、类型检查、生产构建和桌面/移动浏览器验收通过。
- GitHub Pages Actions 成功，线上地址发布并完成实测。
